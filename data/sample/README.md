# サンプルデータ

リポジトリを見た人が、**実行しなくてもデータの中身を確認できる**ようにするための抜粋。

全量は `.gitignore` の対象で、次のコマンドで再生成する。

```bash
uv run sales generate      # 生成 → 合格基準の検査まで一気に行う
uv run sales check-data    # 生成済みデータの検査だけ
```

## transactions.csv の列

1行 = 1受注の1品目。実務の販売管理システムから落とすのと同じ形。

| 列 | 内容 | 備考 |
| --- | --- | --- |
| `受注番号` | 受注の識別子 | 同一受注の複数品目は同じ番号 |
| `明細番号` | 受注内の連番 | `受注番号` と組で一意 |
| `受注日` | 受注日 | **営業日のみ**（土日祝は受注が無い） |
| `顧客コード` / `顧客名` / `顧客所在地` | 顧客 | 東京本社から関東近県へ販売する想定 |
| `拠点` | 拠点 | 東京本社のみ |
| `部署` | 営業部署 | 営業1部 / 営業2部 / ソリューション営業部 |
| `営業担当者` | 担当営業 | **途中で交代することがある** |
| `品名` / `品名カテゴリ` | 商材 | PC 5種・ソフトウェア 5種 |
| `数量` | 数量 | **負の値は返品または取消** |
| `定価` | 定価 | 期間中は変わらない |
| `値引率` | 値引率 | 顧客の交渉力と商材の原価率で決まる |
| `販売単価` | 定価 × (1 - 値引率) | |
| `販売金額` | 販売単価 × 数量 | |
| `原価単価` / `原価` / `粗利` | 原価と粗利 | |

## anomaly_labels.csv の扱い

**このファイルは評価にのみ使い、学習には使わない。**

実務に正解ラベルは存在しない。異常検知の課題では、
ラベルを見ずに検知し、**あとから答え合わせをする**。
うっかり特徴量に混ぜないよう、ファイルごと分けてある。

| 異常種別 | 内容 |
| --- | --- |
| `quantity_typo` | 数量の桁違い（入力ミス）。金額だけ見ると大型案件と区別がつかない |
| `discount_error` | 値引率が承認上限を超えている。**原価割れになるので粗利で検出できる** |
| `push_sale` | 期末の押し込み受注。翌月に取消される。1行だけ見ても分からない |

**「数量が負なら異常」という素朴な検知は、7割が誤検知になる。**
通常の返品が混ざっているため。異常検知の難しさは、
異常を見つけることではなく**珍しいが正常なものを誤検知しないこと**にある。

## customers.csv に無いもの

顧客マスタには **業務的に既知の属性だけ** を入れている。
「いつ離反するか」は載せていない。それは結果であってマスタの情報ではなく、
書いてしまうと離反予測の特徴量にそのまま使えてしまう（リーク）。
