# ビジネス課題と効果

> **⚠️ この文書の数字は、いま再現できません。**
> 2026-08-21 に予測の目的を「発注向けの日次需要予測」から
> 「経営層向けの売上着地予測」へ変更し、データ基盤から作り直しました。
> ここに載っている精度の数字は**前身のシステムのもの**で、現在のコードでは再現しません。
> 説明の枠組み（指標の意味・評価の考え方・チェックリスト）はそのまま使えます。
> 数字は課題①の実装後に差し替えます。→ [予測の目的定義](../objective.md)

**対象読者**: 事業部門・発注担当・経営企画

---

## 先に結論

1. 需要予測の効果は「売上が増える」ではなく、**「在庫と欠品のムダが減る」**という形で出る
2. 効果額は **予測を外す幅 × 1個あたりの損失** で決まる
3. 本システムは外す幅を **3割減らした**（41.1% → 28.7%）
4. **ただし、金額での効果はこのリポジトリでは検証していない。** 計算の型だけを示す

4点目が重要である。効果額は業務ごとの原価・保管費・粗利で決まるため、
それを知らずに「年間◯千万円の効果」と書いた資料は**信用してはいけない**。
ここでは埋めるべき枠だけを用意する。

---

## 1. なぜ予測が要るのか

発注担当は「明日から2週間、何をいくつ仕入れるか」を毎日決めている。
決め方はたいてい次のどれかである。

| よくあるやり方 | 問題 |
| --- | --- |
| 先月と同じだけ頼む | 季節性・曜日の波に対応できない |
| 過去数週間の平均 | 直前の傾向にしか反応しない |
| ベテランの勘 | 属人化する。担当が変わると再現しない |

どれも**間違いではない**。実際、後述のとおり「過去7日の平均」は
かなり強い方法である。問題は、これらが**外す幅を教えてくれない**ことにある。

---

## 2. 損失はどこで出るのか

予測を外すと、外した向きによって違う種類のコストが出る。

```
      予測 < 実需（少なく見た）              予測 > 実需（多く見た）
    ┌─────────────────────────┐      ┌─────────────────────────┐
    │  欠品                    │      │  過剰在庫                │
    │  ・売り逃した粗利        │      │  ・保管費                │
    │  ・客が競合へ流れる      │      │  ・廃棄／陳腐化          │
    │  ・営業の信用低下        │      │  ・資金が寝る            │
    └─────────────────────────┘      └─────────────────────────┘
         見えにくい／記録に残らない          見えやすい／在庫表に出る
```

**この非対称が厄介である。** 過剰在庫は在庫表に数字として残るが、
欠品による機会損失は**どこにも記録されない**。
そのため現場は「とりあえず多めに」に傾きやすく、
気づくと在庫が膨らんでいる、という形になりやすい。

需要予測が効くのは、この**どちらに転ぶかを事前に見えるようにする**点である。

---

## 3. 効果の計算の型

効果額は次の形で計算する。**◯の部分は業務ごとに埋める。**

```
年間の効果額
  = 年間取扱数量
  × 予測を外す割合の改善分
  × 1個あたりの損失額
```

### 埋めるべき数字

| 項目 | どこから取るか | 例（※仮の数字） |
| --- | --- | --- |
| 年間取扱数量 | 販売実績 | 100,000 個 |
| 改善前に外す割合 | **現状のやり方**で測る（後述） | 41.1% |
| 改善後に外す割合 | 本システムの検証値 | 28.7% |
| 1個あたりの損失額 | 保管費・廃棄率・粗利から算出 | 500 円 |

### 計算例（※すべて仮の数字。実測ではない）

```
100,000 個 × (0.411 - 0.287) × 500 円
  = 100,000 × 0.124 × 500
  = 620万円 / 年
```

**この 620万円は例示であって、本リポジトリで検証した数字ではない。**
数量も損失単価も仮に置いたものである。

### 「1個あたりの損失額」の出し方

ここが一番ごまかされやすい。最低限、次の2つを分けて出す。

| | 計算 |
| --- | --- |
| 多く見たときの損失 | 1個あたり（保管費 × 滞留日数 ＋ 仕入原価 × 廃棄率） |
| 少なく見たときの損失 | 1個あたりの粗利 ＋ 失注による将来影響（数値化が難しい） |

**多くの業務で、少なく見たときの損失のほうが大きい。**
粗利をまるごと失うためである。この非対称を無視して平均すると、
効果額を過小に見積もることになる。

---

## 4. 効果を測るときの落とし穴

### 落とし穴1: 比較相手を弱く置く

「予測なし」と比べれば、どんな手法でも良く見える。
**正しい比較相手は、現場が実際にやっている方法である。**

本リポジトリでは「過去7日の平均」を比較相手に置いている。
これは素朴に見えて強い方法で、実際そう簡単には勝てない。

| 比較相手 | 外す割合 |
| --- | --- |
| 前日と同じと考える | 50.1% |
| 先週の同じ曜日と同じ | 48.2% |
| **過去7日の平均** | **41.1%** ← これを比較相手にした |
| 本システム | 28.7% |

一番弱い「前日と同じ」を比較相手にすれば「43%改善」と書けるが、
**それは数字の作り方の問題であって、実力ではない。**

### 落とし穴2: 導入前後を単純に比べる

「導入したら在庫が15%減った」は、季節要因や販売施策の影響を含んでいる。
効果を主張するなら、**同じ期間の同じ商品で、両方の方法を並べて計算する**。

### 落とし穴3: 精度の改善が、そのまま金額にならない

予測精度が上がっても、**発注のルールが変わらなければ効果は出ない。**
「予測が良くなったが、担当者が結局これまで通り発注していた」は普通に起きる。

効果を出すには、予測をどう発注量に変換するかを決める必要がある。
そこが決まっていないなら、**そこから始めるべきである。**

---

## 5. 導入するとしたら、何が必要か

| | 内容 |
| --- | --- |
| データ | 日次の販売実績（商品別・拠点別）を**3年ぶん**。価格と販促の記録も |
| 決めること | 予測を発注量にどう変換するか（誰が決めるか含む） |
| 決めること | 欠品と過剰、どちらをより避けたいか |
| 運用 | 月1回程度の再学習。予測が外れ始めていないかの監視 |
| 体制 | 予測結果を見て発注を判断する担当者 |

**「データはあるが3年分ない」場合、季節性を学習できない。**
2年が下限で、3年あると安定する。

---

## 6. 現時点で正直に言えること・言えないこと

| | |
| --- | --- |
| **言える** | 素朴な方法（過去7日平均）より、外す幅を3割減らせた |
| **言える** | 比較は同じ条件で行い、検証方法を公開している |
| **言える** | どこまでが限界かを数値で示している |
| **言えない** | 実務データで同じ精度が出るか（練習用データで検証しているため） |
| **言えない** | 金額でいくら効くか（業務ごとの原価構造を知らないため） |
| **言えない** | 予測の「幅」が信頼できるか（現在カバー率が不足。改善作業中） |

3つ目の「言えない」は、**在庫の安全余裕を決めるのに直結する欠陥**である。
隠さずに書いておく。
