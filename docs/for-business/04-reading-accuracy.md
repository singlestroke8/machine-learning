# 精度の読み方

> **⚠️ この文書の数字は、いま再現できません。**
> 2026-08-21 に予測の目的を「発注向けの日次需要予測」から
> 「経営層向けの売上着地予測」へ変更し、データ基盤から作り直しました。
> ここに載っている精度の数字は**前身のシステムのもの**で、現在のコードでは再現しません。
> 説明の枠組み（指標の意味・評価の考え方・チェックリスト）はそのまま使えます。
> 数字は課題①の実装後に差し替えます。→ [予測の目的定義](../objective.md)

**対象読者**: 機械学習の知識が無い方。予測システムの成績表を渡された方

---

## 先に結論

**「WAPE 0.287」という数字だけでは、良いか悪いかは判断できない。**

判断には最低3つが要る。

| 要るもの | 本システムの値 |
| --- | --- |
| ① 成績 | 0.287 |
| ② **比較相手**（素朴なやり方） | 0.411 |
| ③ **限界**（これ以上は無理という線） | 0.282 |

この3つが揃って初めて、こう言える。

```
  何もしない                    本システム         これ以上は不可能
  ──────────────────────────────────────────────────────────────
  0.411  ─────────────────────>  0.287  ────────>  0.282
                                   ↑                  ↑
                          3割ぶん改善した      残りはあと 0.005 しかない
```

**改善できる余地の 95.9% を使い切った状態。** ここから先を追っても意味は薄い。

---

## 1. 「0.287」は業務的に何個ぶんか

実際の検証データ（小売、最終の検証期間）で見ると、こうなる。

| | 値 |
| --- | --- |
| 1日1商品あたりの実績 | 平均 **75個** |
| 予測が外した量 | 平均 **21個** |
| 外した量の中央値 | **14個** |

つまり **「75個売れる日に、だいたい14個くらいずれる。ときどき大きく外す」**。

法人取引（BtoB）だと様子が違う。

| | 小売 | 法人取引 |
| --- | --- | --- |
| 実績の平均 | 75個 | 94個 |
| 外した量の**平均** | 21個 | **36個** |
| 外した量の**中央値** | 14個 | **12個** |

**法人取引は、平均36個なのに中央値は12個。**
これは「大半の日は12個程度しかずれないが、たまに極端に外す日がある」ことを意味する。

法人取引では1件の受注が大きく（最大1,500個）、それを外すと一気に数字が悪化する。
**平均値だけ見ていると、この形は見えない。**

## 2. 良し悪しの判断基準

### ① 比較相手より良いか

弱い相手と比べれば、どんな手法でも良く見える。

| 比較相手 | 外し率 | これを比較相手にすると… |
| --- | --- | --- |
| 前日と同じ | 0.501 | 「43%改善！」と書ける |
| 先週の同じ曜日 | 0.482 | 「40%改善！」と書ける |
| **過去7日の平均** | **0.411** | 「30%改善」← 本システムはこれを採用 |

**資料に「◯%改善」とあったら、まず比較相手を確認する。**
一番弱い相手を選んで改善率を大きく見せるのは、資料作りでよく起きる。

### ② 限界までどれくらい残っているか

需要には、原理的に予測できない揺らぎがある。
「たまたま今日は2人多く来店した」はどんなデータからも読めない。

本システムではその限界を **0.282** と推定している。実績 0.287 との差は **0.005**。

**ここから先は、モデルをいくら改良しても最大 1.8% しか良くならない。**
「もっと精度を上げてほしい」という要望に対して、
**「上げても意味がない」と数字で説明できる**のが、この推定の価値である。

> **注記**: この限界の推定は、練習用データだからできることである。
> 実データでは「本当の需要」が分からないため、同じことはできない。
> 法人取引のデータでも算出していない。

### ③ 偏っていないか

平均して同じだけ外していても、**外す向きが偏っていると業務への影響が変わる。**

本システムは **-7.7%**（小売）／**-10.6%**（法人取引）。
**どちらも少なめに出る。** 合計すると実績より1割ほど低い。

| 用途 | 対処 |
| --- | --- |
| 日々の欠品回避 | そのままでよい（むしろ上側の予測を使う） |
| 在庫の総量計画・売上見込み | **補正が必要**。そのまま使うと予算を過小に見積もる |

### ④ 先の予測ほど悪くなっていないか

普通、10日先は1日先より当たらない。**そうなっていない場合は疑ったほうがよい。**

本システムはほぼ横ばい（1日先 0.285 → 14日先 0.288）。
これは優秀なのではなく、**練習用データが規則的すぎる**ためである。
実データなら、先になるほど悪化するのが正常である。

## 3. 予測の「幅」の読み方（ここが現在の弱点）

「80%区間」と名乗るなら、実績の80%がその範囲に収まらなければならない。

```
名乗り            実測
80%  ────────>   小売 73.9%  ／  法人取引 70.1%
```

**足りていない。** 幅が狭すぎる、つまり**「この範囲に収まります」と言いながら、
思ったより外れる**状態である。

### なぜ問題なのか

安全在庫は「最悪どこまで振れるか」から決める。
その幅が実際より狭く出ていると、**安全余裕を過小に見積もる**。
欠品を避けるために幅を使っているのに、その幅が信用できないことになる。

**したがって現時点では、この予測区間を安全在庫の計算に使ってはいけない。**

### 改善の見込み

これは理論的な限界とは無関係の問題で、**確実に直せる**。
検証データの外し方の分布から幅を補正する方法（conformal prediction）が定石で、
次の作業として予定している。

参考までに、区間幅は実績平均の 79〜88% ある（§1 と同じ最終の検証期間で測った値）。
つまり「75個くらい」の予測に対して幅が60個程度。**決して狭くはない。**
それでも収まりきらないのは、需要のばらつきが大きい日が一定数あるためである。

## 4. 数字を渡されたときのチェックリスト

予測システムの成績表を受け取ったら、次を確認する。

- [ ] **比較相手は何か。** 素朴なやり方（過去7日平均など）と比べているか
- [ ] **検証は時間順か。** データをランダムに分けていないか（分けていたら成績は必ず良く出る）
- [ ] **偏りは書いてあるか。** 多め・少なめのどちらに外すか
- [ ] **先の予測の精度が別に出ているか。** 平均値だけ出ていないか
- [ ] **幅の当たり率は書いてあるか。** 「80%区間」が本当に80%か
- [ ] **できないことが書いてあるか。** 良い話しか書いていない資料は疑う
- [ ] **どのデータで測ったか。** 実データか、練習用か

**本システムの資料は、この7項目すべてに答えている。**
逆に言えば、答えていない資料は評価しようがない。

## 5. よくある質問

**Q. 精度100%は目指せないのか**

無理である。需要には予測できない揺らぎがあり、本システムの場合その限界は 0.282。
0 にはならない。**「限界がどこか」を示すことが誠実な回答になる。**

**Q. もっとデータを増やせば当たるようになるか**

量を増やしても限界は下がらない。効くのは**種類**を増やすこと
（天候、イベント、競合の動きなど）である。
ただし本システムの練習用データにはそうした信号が入っていないため、
今の段階では効果を検証できない。

**Q. 最新のAI（大規模言語モデルなど）を使えば精度は上がるか**

この規模・この形式のデータでは、上がらない可能性が高い。
数十万行の表形式データでは、今回使っている手法が最も安定して強いことが知られている。
そもそも**限界まで 0.005 しか残っていない**ので、手法を変える余地がない。

**Q. なぜ「当たった率」ではなく WAPE なのか**

需要予測では「ぴったり当たる」ことがほとんど無いため、
当たった／外れたの2択では評価できない。**どれだけずれたか**で測る必要がある。
