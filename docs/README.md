# ドキュメント

このリポジトリのドキュメントは4層に分かれている。

| 層 | 場所 | 何が書いてあるか | いつ読むか |
| --- | --- | --- | --- |
| **計画** | [`project-plan.md`](project-plan.md) | 何を、どの順で、誰が決めるか | 進め方を確認するとき |
| **成果** | [`../README.md`](../README.md) | 何を作り、どんな結果が出たか | 最初に |
| **前提** | [`data-understanding.md`](data-understanding.md) | データで何が言えて、何が言えないか | **結果の数字を読む前に** |
| **入門** | [`for-business/`](for-business/) | 非エンジニア向けの説明（数式なし） | ML の知識が無い読み手に渡すとき |
| **判断** | [`adr/`](adr/) | なぜその設計にしたか | 実装を変えるとき |
| **経過** | [`log/`](log/) | 何を学び、どこで詰まったか | 進め方の参考に |

**数字を評価する立場で読むなら、[`data-understanding.md`](data-understanding.md) を先に読んでほしい。**
本リポジトリのデータは合成であり、季節性や部署の傾向は生成器に定数で書き込んである。
どこまでが仕込みで、どこからが実際に分析して分かったことかを、そこで分けて記録している。

生成AIを使って開発しているため、**人間がどこで判断したか**を
[`decision-log.md`](decision-log.md) に別立てで記録している。
ADR が「何を選んだか」を書くのに対し、こちらは「AIの提案にどう介入したか」を残す。

加えて、学習を回すたびに自動生成される成果物がある。

| ファイル | 内容 |
| --- | --- |
| [`../reports/model_card.md`](../reports/model_card.md) | モデルの素性と使用上の注意（自動生成） |
| [`../reports/metrics.json`](../reports/metrics.json) | 評価指標の生データ（自動生成） |
| [`experiments.md`](experiments.md) | 試した手法と結果の一覧（手で更新） |

`reports/` 直下は小売（暦日軸）の結果、`reports/b2b/` は法人取引（営業日軸）の結果。
出力先は設定ファイルの `paths.reports_dir` で切り替わる。

## 設計判断（ADR）

| # | 判断 | 要点 |
| --- | --- | --- |
| [0001](adr/0001-record-architecture-decisions.md) | 設計判断を ADR として記録する | 「なぜそうしたか」を残さないと同じ検討をやり直す |
| [0002](adr/0002-synthetic-dataset.md) | 学習データに合成データを使う | 再現性を最優先。実データとの差分は明示する |
| [0003](adr/0003-polars-over-pandas.md) | データ処理に Polars を使う | 系列ごとの時系列演算で順序事故を起こさないため |
| [0004](adr/0004-horizon-aware-features.md) | **特徴量を horizon 基準で打ち切る** | **本リポジトリの中核。リークを構造的に防ぐ** |
| [0005](adr/0005-expanding-window-cv.md) | 拡大窓の時系列CVを使う | ランダム分割は検証を必ず楽観的にする |
| [0006](adr/0006-primary-metric-wape.md) | 主要指標に WAPE を使う | ベースラインと理論下限で挟んで初めて意味を持つ |
| [0007](adr/0007-quantile-regression.md) | 分位点回帰で予測区間を返す | 点予測だけでは発注量を決められない |
| [0008](adr/0008-experiment-tracking.md) | MLflow で実験を記録する | 記録の失敗が学習を止めない設計にする |
| [0009](adr/0009-split-serving-and-training-deps.md) | 推論と学習の依存を分ける | 推論イメージに学習用ライブラリを持ち込まない |
| [0010](adr/0010-business-day-timeline.md) | 時間軸を「ステップ」として抽象化する | 暦日と営業日を同じコードで扱う。法人取引は土日祝に受注が無い |

最初に読むなら **0004**（特徴量のリーク防止）と **0006**（評価の枠組み）を勧める。
このプロジェクトの技術的な中身はほぼこの2つに集約されている。

## 学習ログ

日々の作業で「何を学び、何に詰まり、どう解決したか」を残している。

- [`log/`](log/) — 日付ごとの記録
- [`log/TEMPLATE.md`](log/TEMPLATE.md) — 新しい記録を書くときの雛形

うまくいったことより、**詰まったこととその解決**を厚く書くようにしている。
成功例は再現しにくいが、失敗の記録は次に同じ壁に当たったときそのまま使えるため。
