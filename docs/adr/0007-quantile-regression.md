# ADR-0007: 分位点回帰で予測区間つきの予測を返す

- 状態: 採用
- 日付: 2026-08-16

## 背景

「明日この商品は 100 個売れます」と伝えても、発注担当は何個仕入れればよいか決められない。
決めるために必要なのは、需要の**ばらつき**の情報である。

- 安定して 100 前後なら、100 個仕入れればよい
- 60〜160 の幅で動くなら、欠品を避けたいなら 140 個ほど必要になる

点予測しか返さないモデルは、この判断材料を渡していない。
在庫の意思決定では、点予測の精度より区間の質のほうが効く場面が多い。

## 決定

LightGBM の分位点回帰（`objective="quantile"`）で q = 0.1 / 0.5 / 0.9 の3本を学習し、

- **点予測** = q=0.5（中央値）
- **予測区間** = q=0.1 〜 q=0.9（公称 80% 区間）

を返す。API のレスポンスも `point` / `lower` / `upper` の3つ組にした。

分位点は独立に学習するため、まれに大小関係が逆転する（分位点交差）。
これは予測後に行ごとにソートして解消する。

## 理由

**なぜ分位点回帰か（点予測＋正規分布の仮定ではなく）**

点予測に残差の標準偏差を掛けて区間を作る方法もある。実装は簡単になる。
しかし需要は右に歪んだカウントデータで、正規分布から大きく外れる。
特に需要の小さいSKUでは、正規近似の区間が**負の値を含む**という不合理が起きる。

分位点回帰は分布の形を仮定しないので、この問題が起きない。
また、需要水準によってばらつきの大きさが変わる（大きく売れるSKUほど絶対的なばらつきも大きい）が、
分位点回帰は特徴量に応じて区間幅を変えられるので、この性質も自然に扱える。

**なぜ 0.1 / 0.9 か（0.05 / 0.95 ではなく）**

裾に行くほど、その分位点を推定するのに使えるデータが減り、推定が不安定になる。
80% 区間なら、各裾に 10% のデータが効くので比較的安定する。
在庫の安全在庫を決めるには 90 パーセンタイル程度で実用上足りることが多い。

**なぜ q=0.5 を点予測にするか**

WAPE は絶対誤差の指標であり、これを最小化する予測は条件付き**中央値**である（平均ではない）。
主要指標（ADR-0006）と学習目的を揃えることで、
「学習では何かを、評価では別の何かを最適化している」というずれを避けている。

**なぜ3モデルを独立に学習するか**

LightGBM は1回の学習で複数の分位点を同時に出せない。
マルチターゲット化する方法もあるが、実装が複雑になる割に得られるものが小さい。
3倍の学習時間（実測で合計 26 秒程度）は許容範囲だった。

## 検証で分かった問題

**区間カバー率が公称を下回っている。**

| | 値 |
| --- | --- |
| 公称カバー率 | 0.80 |
| 実測カバー率 | **0.734** |

つまり、80% の区間だと言いながら実際には 73.4% しか実績を含んでいない。
在庫の安全余裕を過小に見積もることになるので、このまま在庫計画に使うのは危険である。

原因は分位点回帰の過学習と考えている。木の本数を減らした試行（`--fast`）では
カバー率 0.844 と、逆に公称を上回っていた。
木を増やすほど分位点の推定が学習データに寄り、区間が狭くなる。

**この問題は隠さず、`reports/model_card.md` と README に明記している。**
実務でこのモデルを使うなら、以下のいずれかの対処が要る。

1. **Conformal prediction による較正** — 検証期間の残差分位点から区間を補正する。
   分布の仮定を置かずに、カバー率を保証できる。最も筋が良い。
2. 分位点モデルだけ正則化を強める（木を浅く、本数を減らす）
3. 区間の目標をカバー率で直接最適化する

現時点では 1 を次の改善候補としている（`docs/log/` に記録）。
**「精度が出た」で終わらせず、区間の質まで点検したからこそ見つかった問題である。**

## 結果

**得たもの**

- 発注量の判断に使える形の出力
- 分布の形を仮定しないので、需要の歪みや水準依存のばらつきに対応できる
- 予測が負にならない（0 で下限を切っている）
- カバー率という点検軸が手に入り、モデルの弱点が可視化された

**諦めたもの**

- 学習時間が3倍になる
- 分位点交差の後処理が必要（ソートで対処）
- 区間の較正が未実施。現状のカバー率は公称を下回っており、そのままでは在庫計画に使えない
