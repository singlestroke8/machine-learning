# ADR-0010: ディープラーニングを採用せず、勾配ブースティング木を使う

- 状態: 採用
- 日付: 2026-08-16

## 背景

本プロジェクトは当初、「ディープラーニングのポートフォリオ」として企業に提出することを
想定していた。一方、実装は LightGBM（勾配ブースティング木）で進んでおり、
目的と手段が整合していなかった。

そこで、ディープラーニングを導入すべきかを正面から検討した。
この ADR は、**「検討せずに使わなかった」のではなく「検討したうえで退けた」**ことを
記録するために書いている。面談で「なぜDLを使わないのか」と問われたときの回答でもある。

## 決定

**ディープラーニングは採用せず、勾配ブースティング木（LightGBM）を使う。**

分位点回帰（q = 0.1 / 0.5 / 0.9）による予測区間の出力も、現行の LightGBM 実装のまま続ける。

## 理由

### 1. データの規模と性質が、DLの前提を満たしていない

表形式データにおいて、勾配ブースティング木がニューラルネットを上回るのは
広く知られた経験則である。DLが優位に立つのは次のいずれかの場合に限られる。

- データ量が桁違いに多い（系列数が数千〜数万）
- 非構造データを扱う（画像・音声・自然言語）
- 系列間の複雑な相互作用が支配的である

本プロジェクトの規模を、DLが実績を上げている事例と並べると差は明らかである。

| | 系列数 | 期間 | 総行数 |
| --- | --- | --- | --- |
| **本プロジェクト（想定）** | **20〜30** | **3年（1,096日）** | **22,000〜33,000** |
| M5 Forecasting（DL勢が上位に入ったコンペ） | 30,490 | 1,941日 | 約 5,900万 |

系列数で3桁、行数で3桁の差がある。この規模でニューラルネットを使うと、
系列埋め込みが十分に学習されないまま過学習し、GBDTに劣る結果になる可能性が高い。

### 2. 予測区間の要件が、すでにGBDTで満たされている

DL系の時系列モデルを導入する主な動機のひとつは、確率的予測（DeepAR、TFT など）である。
しかし本プロジェクトでは、LightGBM の分位点回帰で
点予測と 80% 予測区間の両方をすでに出力できている（ADR-0007）。

つまり「DLでなければ得られない出力」が存在しない。

### 3. 改善の余地が、数値的に否定されている

これが決定的な理由である。

本プロジェクトには**誤差の理論下限（ノイズフロア）の推定**がある
（`src/demand_forecast/analysis.py`、`uv run dfc noise-floor`）。
需要は確率的に発生するため、真の期待需要を完全に知っていても実績は当てられない。
その「原理的に取り除けない誤差」を測ったものである。

| | WAPE |
| --- | --- |
| 最良ベースライン（移動平均） | 0.4107 |
| **現行モデル（LightGBM）** | **0.2859** |
| 理論下限（真の期待需要を知る予言者） | 0.2816 |

**学習可能な余地の 96.7% を、すでに回収している。残りは 0.0043 しかない。**

どれほど高度なモデルを持ち込んでも、改善の上限は 1.5% である。
「モデルを変えれば精度が上がるかもしれない」という期待が、
測定によって否定されている状態にある。

この状況で DL を導入するのは、**測定結果を無視した意思決定**であり、
実務ではむしろ減点対象になる。

### 4. 運用コストが釣り合わない

| 項目 | GBDT（現行） | DL を入れた場合 |
| --- | --- | --- |
| 学習環境 | CPU のみ | GPU が実質必須 |
| 学習時間 | 数分 | 数十分〜数時間 |
| 推論イメージ | 学習依存を分離済み（ADR-0009） | PyTorch で数百MB増 |
| 依存の管理 | 軽い | CUDA・cuDNN のバージョン整合が発生 |

期待できる改善が最大 1.5% であることを踏まえると、このコストは正当化できない。

## 検討した代替案

| 案 | 内容 | 退けた理由 |
| --- | --- | --- |
| B | GBDT と DL の両方を実装して比較する | 実装力の証明にはなるが、理由3により**結果は事前に予想がつく**。「予想がつく実験」に工数を割くより、予想がつく根拠（理論下限）を示すほうが価値が高いと判断した |
| C | 画像・自然言語など、DLが本領を発揮する題材へ変更する | 需要予測で積み上げたリーク防止の設計、時系列CV、理論下限の枠組みをすべて捨てることになる。これらは題材を変えても再現しにくい資産である |

### 案 B について補足

「両方実装して比較する」は一般には良い方針である。実際、当初はこれを推奨していた。

退けた決め手は、**理論下限との距離がすでに測れていた**ことにある。
通常は「やってみないと分からない」ので比較実験に価値があるが、
本プロジェクトでは「やっても最大1.5%」と定量的に分かっている。

比較実験の価値は「不確実性を減らすこと」にある。
不確実性がすでに小さいなら、実験の価値もその分小さい。

## 結果

### 得たもの

- 手法選定の根拠を、感覚ではなく**数値で説明できる**
- 推論イメージが軽いまま保たれる（GPU不要、CPU で数分の学習）
- 限られた時間を、より効果の大きい課題（予測区間の較正、データ品質）に回せる

### 諦めたもの

- **「ディープラーニングを実装できる」ことの直接的な証明。**

  これは実在するコストである。DLの実装経験を求める求人には、この成果物では応えられない。
  面談で問われた場合は本 ADR をもって回答する。
  「使えないから使わなかった」のではなく「測って退けた」という説明になる。

- DL系ライブラリ（PyTorch、neuralforecast など）の運用経験

## この判断が変わる条件

次のいずれかが成立したら、この ADR を見直す。

1. **系列数が数千規模になる** — 系列埋め込みが機能する規模に達したとき
2. **非構造データを特徴量に加える** — 商品画像、レビューテキスト、店舗の位置情報など
3. **理論下限との差が開く** — データが増え、まだ学習できていない構造が残っているとき
4. **予測区間の較正が、分位点回帰の枠内で解決できないと分かったとき**

いずれも「DLが流行っているから」ではなく、
**測定結果に基づいて必要性が生じたとき**に限る。
